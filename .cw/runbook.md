# Developing mambo-power with Codewright

Epic 01 (waves M1–M9) was built with the bionic canonical-sdlc process; its records stay in `.bionic/`. Work from here on runs through Codewright, one intake per step below.

## Setup (already done in this repository)

- `cw.yaml` is written by hand: Codewright's `/init` detects gates only from `package.json`. The gates are `ruff check`, `ruff format --check`, `mypy`, the full `pytest`, the tutorial notebooks under nbmake, and `mkdocs build --strict`, with `worktree.setup: uv sync --frozen --all-groups` so a fresh worktree has the dev and docs tools. The test gate carries a raised `timeoutMin`: the full suite takes 15–20 minutes, past Codewright's 10-minute default.
- `WORKFLOW.md` is read from this checkout and prepended to every agent prompt (task worktrees are cut from `HEAD`, so an uncommitted copy still works, but commit it so the contract travels with the repository); `.cw/roles/` tailors the planner, implementer and reviewer.
- Routing: planner and escalate → `claude-fable`, everything else → `claude-opus`.

## The run loop

Inside `claude`, started in this repository: `/codewright:runbook` lists the steps and which have run; `/codewright:next` starts the first one nobody has started and parks at the plan. Approve a plan only if every task names a test file and what it asserts, has a specific lease that overlaps no other task's, and is one sitting's work; otherwise say no with a reason. The work lands on `cw/integration/<runId>`; review it, then land it as **one squash commit with a Conventional Commit subject** — `git merge --squash cw/integration/<runId>` and `git commit -m "feat(cases): ..."` — never `--ff-only`: Codewright's task commits are titled `codewright: T1 <attemptId>`, and python-semantic-release computes the next version from the subjects that reach `main`.

A step's text is how Codewright recognises it: edit a blockquote freely before its run starts, never after.

## Steps

**Run 1 — bundled cases: tutorials and examples work from `pip install mambo-power` alone**

> Goal, in the owner's words: `pip install mambo-power` must be able to load the fixtures, and nothing a reader runs may need a clone of the repository on disk. Today all four tutorials (`docs/tutorials/*.ipynb`) and the scripts in `examples/` load MATPOWER and PSS/E RAW files by repository-relative path (`../../fixtures/matpower/case14.m`, `fixtures/case14_v33.raw`), while the wheel ships only `src/mambo_power`, so a pip-only reader gets `FileNotFoundError`. This reverses ADR-013 in `docs/design/decisions.md`; read it first.
>
> 1. **Package data.** Move with `git mv`, bytes unchanged, the reader-facing case files into the package under `src/mambo_power/cases/data/`: the six MATPOWER cases in `fixtures/matpower/` (`case14.m`, `case30.m`, `case_ieee30.m`, `case57.m`, `case118.m`, `case300.m`), the four `fixtures/matpower/derived/` variants (kept under `data/derived/`), `fixtures/case14_v33.raw`, and the provenance files that cover them (`PROVENANCE.md`, `SOURCES.md`, `derived/PROVENANCE.md`, `PROVENANCE-raw.md`) — the licence notes travel with the data. `fixtures/synthetic_quirks_v33.raw` is test-only and moves under `tests/`. Exactly one copy of each file: `tests/_fixtures.py` and every test that reads a fixture point at the new location, the verbatim sha256 checks keep passing, and `fixtures/` no longer exists.
> 2. **API.** A new public module `mambo_power.cases`, stdlib `importlib.resources` only: `available() -> list[str]` (sorted relative names such as `"case14.m"`, `"derived/case14_roles.m"`, `"case14_v33.raw"`); `path(name: str) -> pathlib.Path` (unknown name raises `ValueError` listing what is available); `load(name: str) -> Network` for MATPOWER cases, accepting `"case14"` or `"case14.m"`, through the existing `io.matpower` importer. Docstrings per the docstring rule, an API page `docs/api/cases.md` wired into `mkdocs.yml`, and a short manual section. Unit tests: every name in `available()` resolves to an existing file; `load` returns a valid `Network` for every top-level `.m` case; an unknown name raises `ValueError` naming the available cases.
> 3. **Packaging proof.** `pyproject.toml`: the wheel carries `cases/data/**` (and still `py.typed`, still no `tests/`); the sdist allow-list follows the new paths. `.github/workflows/ci.yml` `install-smoke`: replace the rejection of `fixtures/` in the wheel with an assertion that the wheel contains `mambo_power/cases/data/case14.m` and `mambo_power/cases/data/PROVENANCE.md`, keep rejecting `tests/`, update the sdist `required` list, and in the clean wheel venv run from a temporary directory outside the checkout: `from mambo_power import cases, pf; print(pf.solve_dc(cases.load("case14")).generators[0].p_mw)`.
> 4. **Readers.** Every script in `examples/` and all four tutorials load data only through `mambo_power.cases` — no `fixtures/` path and no repository-relative path. `tests/unit/test_examples_run.py` runs each script with its working directory set to a fresh `tmp_path` instead of the repository root, and raises the default `BUDGET_S` to 180 s: it is a hang guard, and 60 s trips under parallel CPU load (`12_agent_market` takes 15 s alone and failed at 60 s under load). Add a unit test that fails if any file under `examples/` or `docs/tutorials/` contains the string `fixtures/`. Remove the clone-required caveats — the tutorial cells that state it, `docs/tutorials/index.md`, `docs/getting-started.md`, `docs/examples/index.md` ("Run any of them from a clone"), and the README's Install and Quick start — and change the `fixtures/...` paths in `README.md`, `docs/index.md` and `docs/manual/*.md` to the `cases` API. Leave the history in `docs/changelog.md` and everything under `.bionic/` alone.
> 5. **Decision record.** Append ADR-014 to `docs/design/decisions.md`: the bundled cases ship in the wheel (about 200 KB of text, the same redistribution the sdist already made, provenance included) so tutorials and examples need only `pip install mambo-power`; set ADR-013's status line to superseded by ADR-014.
>
> Done means all gates pass — `ruff check`, `ruff format --check`, `mypy`, the full `pytest`, `pytest --nbmake docs/tutorials`, `mkdocs build --strict` — and a wheel built with `uv build`, installed into a fresh venv and run from a directory outside the repository, loads `cases.load("case14")` and solves it. No new runtime dependency. Commits are `feat`/`docs`/`test` Conventional Commits.

**Run 2 — finish the bundled-cases move: delete `fixtures/`, re-point tests, packaging, CI and prose**

> Run 1 put `mambo_power.cases` on `main` with the case data copied into `src/mambo_power/cases/data/`, rewrote every example and tutorial to load through it, and recorded ADR-014 in `docs/design/decisions.md` (read it first). It stopped at its third task because implementers could not delete or move files; Codewright now lets them use `git rm` and `git mv`. Finish the job, so exactly one copy of each case file exists and nothing a reader runs or reads needs a clone.
>
> 1. **Remove `fixtures/`.** Confirm by sha256 that each of the 15 files under `fixtures/` other than `synthetic_quirks_v33.raw` is byte-identical to its copy under `src/mambo_power/cases/data/` (same relative layout: `fixtures/matpower/X` ↔ `data/X`, `fixtures/matpower/derived/X` ↔ `data/derived/X`, `fixtures/case14_v33.raw` and `fixtures/PROVENANCE-raw.md` ↔ `data/`), then `git rm` them. Move the test-only file with `git mv fixtures/synthetic_quirks_v33.raw tests/fixtures/synthetic_quirks_v33.raw`. `fixtures/` must not exist afterwards.
> 2. **Re-point the tests.** `tests/_fixtures.py` `FIXTURES_DIR` becomes `<repo>/src/mambo_power/cases/data`; `tests/unit/test_io_psse_raw.py` reads case14's RAW and `.m` from the packaged data and the quirks file from `tests/fixtures/`; `tests/unit/test_jobs.py` stops using `FIXTURES_DIR.parent / "case14_v33.raw"` and uses `cases.path("case14_v33.raw")`; `tests/unit/test_cases.py` drops its comparison against `fixtures/`; update the stale `fixtures/...` paths in docstrings of `tests/unit/test_fixture_case300.py` (its sha256 checks stay unchanged and passing), `test_fixtures_derived.py`, `test_fixtures_pwl.py`, `test_io_pandapower_json.py`, `tests/parity/test_pandapower_json_vs_pandapower.py` and the `src/mambo_power/io/pandapower_json.py` module docstring.
> 3. **Packaging and CI.** `pyproject.toml`: drop `/fixtures` from the sdist allow-list and fix its comment; state in a comment that the wheel carries `cases/data/**` (hatch ships non-Python files under the package). `.github/workflows/ci.yml` `install-smoke`: the wheel listing must contain `mambo_power/cases/data/case14.m` and `mambo_power/cases/data/PROVENANCE.md` and still no `tests/`; the sdist `required` list uses `src/mambo_power/cases/data/case14.m`; the clean wheel venv runs `from mambo_power import cases, pf; print(pf.solve_dc(cases.load("case14")).generators[0].p_mw)` from a temporary directory outside the checkout.
> 4. **Prose.** Remove every clone-required caveat and every `fixtures/...` path from `README.md` (Install, Quick start with `cases.load("case14")`, and the licence note saying the bundled cases ship inside the package with `PROVENANCE.md`), `docs/getting-started.md` (keep an unqualified `pip install mambo-power` block so `scripts/check_pypi_sequencing.py` still passes), `docs/index.md`, `docs/examples/index.md`, `docs/tutorials/index.md`, and `docs/manual/*.md`; rewrite the `## Bundled fixtures` section of `docs/manual/formats.md` as `## Bundled cases`, documenting `cases.available()`, `cases.path()` and `cases.load()` with a runnable snippet and a link to `../api/cases.md`. Leave `docs/changelog.md` and `.bionic/` alone. `examples/13_interop.py` also imports pandapower and PyPSA, which are dev-only: its module docstring and its entry in `docs/examples/index.md` must say it needs `pip install pandapower pypsa`, since every other example runs on `pip install mambo-power` alone.
>
> Done means all gates pass with `fixtures/` gone, `grep -rn "fixtures/" README.md docs src tests pyproject.toml .github examples` finds only `tests/fixtures/` references, and a wheel from `uv build` installed into a fresh venv solves `cases.load("case14")` from outside the repository.
